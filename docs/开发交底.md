# 打工人记账器 · v1.6 开发交底

**范围**：只做下面 6 项，法定节假日、调休累计、托盘、安装包都不在本次范围。
**文件**：几乎所有改动都在 `src/app.js`，UI 改动在 `src/index.html`（样式在 `src/style.css`）。
**总原则**：金额只允许在 `calc()` 里算一次，其它地方不得再自己算 `perSec`；`cfg.settled` 是历史金额，任何改动都不得重算它。

---

## 改动 1｜请假要真的扣钱（最高优先级）

**文件**：`src/app.js`

**现状问题**：请假只是把 `running` 置 false、显示归零。`segments` 里那段 `{from, to: null}` 没闭合，`autoSettle()` 遇到请假直接 return，计时在后台继续跑。取消请假后 `manualSeconds()` 把整段一次性算回来。实测：09:00 打卡 → 12:00 请假 → 18:00 取消，金额从 136.37 变成 409.11。

**要改成**：
1. 新增 `enterLeave(now)`：
   - 若 `segs()` 非空且最后一段 `to == null`，把 `last.to = now` 闭合
   - 立即结算已工作部分：`clockFrom === 'click'` 用 `manualSeconds(now)`，`schedule` 用 `scheduleSeconds(now, b)`
   - 结算走现有 `settle()`，但**结算后不要清 `leaves`**
   - `cfg.leaves[dayKey(now)] = true`，`save()`
2. 新增 `exitLeave(now)`：
   - `delete cfg.leaves[dayKey(now)]`
   - 若当前是工作日且未到下班，新开一段 `{from: now, to: null}`（打卡模式），或清 `doneShift`（定时模式）
   - `save()`
3. `#btnLeave` 的点击处理从「只切 `cfg.leaves`」改为调用 `enterLeave` / `exitLeave`
4. `autoSettle()` 里那句 `if (cfg.leaves[dayKey(now)]) return;` 保留（因为 enterLeave 已经结算过）

**验收**：09:00 打卡 → 10:00 请假 → 18:00 取消 → 今日已赚 = 1 小时金额，已工作时长停在 `01:00:00`，不回到 9 小时。

## 改动 2｜改参数不能重算当天已赚

**文件**：`src/app.js`

**现状问题**：`calc().perSec` 每次实时读 `cfg.salary`，而 `manualSeconds()` 累计的是绝对时长。改月薪 8000→16000，已工作的 3 小时从 136.37 直接变 272.78。

**要改成**：
1. 新增 `settleIfRunning(now)`：
   - 若 `segs()` 有内容，按**当前（旧）参数**结算到 `now` 并 `save()`
   - 返回 `true` 表示「之前正在计时」
2. 在 `saveSheet()` 里，**写入新参数之前**先调用它，记住返回值 `wasRunning`
3. 写入新参数之后，若 `wasRunning === true`，新开一段 `{from: now, to: null}`，保证计时连续
4. 不要清 `cfg.settled`、不要清 `cfg.leaves`

**验收**：3 小时赚 136.37 后把月薪改成 16000 → 已赚仍是 136.37，只有后续每秒按新单价增长。

## 改动 3｜今日已赚封顶日薪，超出转加班时长

**文件**：`src/app.js`

**现状问题**：秒薪分母是班次有效工时（8h），分子是实际在岗（9h），9÷8 导致「日薪 364、已赚 409」。

**要改成**：
1. `calc()` 里的 `perSec` 改为 `日薪 ÷ (H × 3600)`，`perDay` 直接返回日薪（不再由 `perHour × 分钟数` 反推）
2. `render()` 里把 `workSeconds(now)` 的结果拆两段：
   - `billable = Math.min(sec, H × 3600)`
   - `overtime = Math.max(0, sec - H × 3600)`
3. 今日已赚 = `billable × perSec`，**永远不超过日薪**
4. 新增一行 UI（主数字下方，`overtime > 0` 时才显示）：「加班 1:23」
5. 本次只显示今日加班时长，不做月度累计和调休折算

**验收**：09:00–18:00 出勤显示 ¥364（不是 ¥409）；干到 19:00 金额仍 ¥364，同时出现「加班 1:00」。

## 改动 4｜新增「每日有效工时」输入

   位置放在「午休」下面、「计时方式」上面

3. `DEFAULTS` 新增 `dailyHours: null`（`null` = 按班次自动推导）
4. 新增 `effectiveMinutes()`：`dailyHours` 有值就用 `dailyHours × 60`，否则按 `下班 − 上班 − 午休` 推导
5. `calc()` 用 `effectiveMinutes()`
6. 该输入**只在「打卡那一刻」模式下显示**，定时模式下隐藏（定时模式的工时由班次决定）
7. 保存时写 `cfg.dailyHours`，清空则置 `null` 回到推导值

**验收**：填 7 → 秒薪 = 日薪 ÷ 7 ÷ 3600；干满 7 小时即达日薪，第 8 小时起进入加班。

## 改动 5｜定时模式早退结到下班时间

**文件**：`src/app.js` 的 `clockOutSched()`

**现状**：
```js
settle(b.start, scheduleSeconds(Math.min(Date.now(), b.end), b));
```
**改成**：
```js
settle(b.start, scheduleSeconds(b.end, b));
```
**同时**把提示文案从「计薪到 18:00 为止，早退也不扣」改成「计薪按设定班次，实际打卡不影响金额」。

**依据**：定时模式的金额以用户填的班次为准，不看实际打卡时刻。

**验收**：09:00 打卡、17:00 点下班 → 金额仍为全天日薪。

## 改动 6｜模式卡改成「保存后生效」

**文件**：`src/app.js`

**现状问题**：点卡片直接写 `cfg.clockFrom` / `cfg.autoRun`，但不写 localStorage。点「收起」后界面已经按新模式跑，重启又变回去。实测：点「定点打卡」后 `storedMode` 仍是 `click`，界面却提示「08:30 起可打卡」。

**要改成**：
1. 新增模块级变量 `pendingMode` / `pendingAuto`
2. 点卡片只改这两个变量 + 重绘选中态，不碰 `cfg`
3. `openSheet()` 用 `cfg` 初始化它们
4. `updateModeHint()` 读 `pendingMode`，不读 `cfg`
5. `saveSheet()` 时才把 `pendingMode` / `pendingAuto` 写进 `cfg`

**验收**：点「定点打卡」→ 点「收起」（不保存）→ 界面行为仍是「打卡那一刻」；重启后状态一致。

## 注意事项（给开发的三条）

1. **`calc()` 是唯一入口**。改完后全项目搜 `cfg.salary`，除 `calc()`、`updateSalaryEcho()`（表单回显）外不应有第三处。
2. **`cfg.settled` 只增不改**。它是历史金额，任何参数变更、模式切换都不得重算或清零。
3. **改完不要动 `doneShift` 的语义**，它表示「今天这一班已收工」，仍以 `b.start` 作为标识。

## 自测方法

这个应用高度依赖时间，本地逐条等不现实。仓库里已有 `.preview/shot-electron.js`，可以启动应用并注入动作；关键是覆写 `Date.now` 来跳时间：

```js
// 跳到今天 12:00
const rn = Date.now;
const t = new Date(); t.setHours(12,0,0,0);
const off = t.getTime() - rn();
Date.now = () => rn() + off;
```

注意 `new Date()` 不带参数时不走 `Date.now`，所以控制台里看到的时间仍是真实时间，但应用逻辑全部走 `Date.now()`，模拟是有效的。

**必须逐条跑过的 6 条**：

| # | 场景 | 期望 |
|---|------|------|
| 1 | 09:00 打卡 → 10:00 请假 → 18:00 取消 | 已赚 = 1 小时金额，工时 01:00 |
| 2 | 3 小时赚 136.37 → 月薪改 16000 | 已赚仍 136.37，之后按新单价 |
| 3 | 定时模式 09:00–18:00 | 已赚 = ¥364，不出现 ¥409 |
| 4 | 定时模式 17:00 点下班 | 已赚仍 = ¥364 |
| 5 | 打卡模式填 7h，实际干 8h | 达日薪后出现「加班 1:00」，金额不涨 |
| 6 | 点模式卡后点收起 | 行为不变；重启后一致 |
